# Writing rules

These are the instructions the model receives, kept apart from the code so they can be read, discussed and versioned.

| File | What it holds | When it is sent |
| --- | --- | --- |
| `assessment.md` | Rules for the whole assessment: what it is for, who reads it, how it is written, "nothing invented", the three kinds of content (facts, clinical reasoning, proposals: proposals only in the case formulation, never in prose until she accepts them), the format for pasting into ABA Matrix. | On every call, as part of the cached prefix. |
| `guide.md` | The assessment as a whole: what it is for, the clinical reasoning chain (sources, deficits and behaviors, functions, interventions, goals, caregiver training, generalization, discharge, recommendations), the map of all 22 sections (what each owns, refers to and must match) and what must match everywhere. | On every call, whole, as part of the cached prefix (owner's decision, 2026-11-23). |
| `payers/florida-medicaid-molina.md` | Facts from the Florida Medicaid policy (Dec. 2024) and the Molina guide (Jul. 2026) that bear on authorization: who qualifies, the instruments, why requests are returned, intensity, what the assessment and plan must contain (6.2.2), the FBA and behavior plan, schedule, transition and discharge; then our mapping of them onto the sections and a payer readiness list. Only what those two texts say, except the mapping, which is marked as ours. | On every call, as part of the cached prefix. |
| `instruments.md` | How to read the Vineland-3 and the BASC-3 PRQ (means, standard deviations, the direction of each scale), the FBA tools (FAST, MAS, ABC and scatterplot data), the ABLLS-R, preference assessments, and how indirect and direct evidence combine into a hypothesized function. Not from the payers; marked as pending confirmation by the BCBA. | On every call, as part of the cached prefix. |
| `requests.md` | How each request of the section workspace works: her sections (final, never contradicted), her standing instructions, her session notes (used in the section that owns their fact), and the kinds of request (draft, change, paragraph change, improve; a shorter text keeps its incidents). | On every request of the section workspace, as part of the cached prefix. Not in `pnpm phase0`. |
| `sections/medical-necessity.md` | What the Medical Necessity section is for, the structure the BCBA requires and what a good one looks like. | Only when generating that section, after the cached prefix. |
| `style.md` | How she writes: voice and person, attribution, her patterns, explaining numbers, sentences she would not write, terms, length. Built from her patterns; points only she can settle are marked "pending her answer". | On every call, whole, as part of the cached prefix (owner's decision, 2026-11-23). |
| `sections/*.md` (the other eight) | Each narrative section of the report: what it is for, what to write, its gaps, and what the decisions file does not settle yet ("Not yet settled with the BCBA"). Written from the decisions file only; marked unconfirmed until the BCBA reviews them. | Only when generating that section. |

Each file starts with an `id` and a `version`. A section's file may also give `paragraphs: 6-9` and `words: 900-1500`: the structure check beside the text uses them, and a section without them is checked for plain paragraphs only. When the content changes, the version goes up; every output stores the versions that produced it (`rulesVersions` in each run's JSON).

The order matters for cost: the system files (`assessment.md`, `guide.md`, `style.md`, the payer facts and the instruments) are the same for every section and every case, and a case's sources are the same for every section of that case. That prefix is written once to the provider's cache and the other sections read it at a fraction of the price. Each section's rules go last so they don't break that prefix.
