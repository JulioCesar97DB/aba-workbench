# The desktop app

How aba-workbench is put together since it moved from a hosted Next.js site to a desktop app (2026-11-22). Electron with a React interface built by Vite; electron-vite builds it and electron-builder packages it. Versions: see `package.json`.

## Processes

- **Main process** (`src/main/`, Node.js). Owns the window and everything with access to the computer: the provider layer in `src/lib/`, the rules files, the cases folder (every file operation on a case), and the credentials file. Keys and tokens live here and in that file, never in the interface ([connections.md](connections.md)).
- **Preload** (`src/preload/index.ts`). Runs sandboxed before the interface loads and exposes `window.aba`: the functions below and nothing else.
- **Interface** (`src/renderer/`, React; organized as described in [interface.md](interface.md)). Runs sandboxed, without Node.js. It can reach the main process only through `window.aba`. ESLint refuses imports of `electron`, `node:*` or main-process code in it (types excepted).

`pnpm phase0` runs the same provider layer from a plain Node script, through the same function the app uses (`runGeneration` in `src/lib/generate.ts`), with no window and no server.

## What the interface can call

Defined in `src/shared/api.ts`, exposed by the preload, answered in `src/main/ipc.ts`:

| Function | What it does |
| --- | --- |
| `getAppInfo()` | The app's name and version, and `developmentBuild`: true when it runs from the repository (not packaged), which shows the development check's link. |
| `getSettings()` | The saved screen language, or the default. (The cases folder's path is in the settings file too, but only `getCasesFolder` shows it.) |
| `setLanguage(language)` | Saves the screen language, `"en"` or `"es"`; anything else is refused. Returns the settings as saved. |
| `getCasesFolder()` | Where the cases are: the folder's path as text to show, whether it is the default, and whether it can be used (`ready`, `not-created-yet`, `missing`, `not-a-folder`, `not-allowed`, `not-writable`). |
| `chooseCasesFolder()` | Opens the system's folder dialog. A folder chosen there that can be used becomes the cases folder and is saved in the settings file; one that cannot is refused and nothing changes. Takes no argument. |
| `showCasesFolder()` | Opens the cases folder in Finder or Explorer. |
| `listCases()` | The cases in the cases folder, newest first, and the folders there that cannot be opened, with the reason. |
| `createCase({ label, clientAge })` | Makes a case's folder and data file. The label must pass `checkCaseLabel`; the age is `{ years, months? }` or nothing. |
| `openCase(caseId)` | Reads a case by its id, and saves its list of PDFs if the folder's PDFs changed. |
| `showUnreadableFolder(folderName)` | Shows a folder Home last listed as unreadable in Finder or Explorer, selected. Any other name (a case, a hidden folder) is not shown. |
| `addTextSource(caseId, { type, title?, date?, text })` | Adds a pasted text to a case. Answers with the case's sources as saved (`CaseSources` in `src/shared/sources.ts`), or why not (`not-saved`, `case-full`, `case-unavailable`). |
| `changeSource(caseId, sourceId, { type?, title?, date?, text? })` | Changes a source: only the keys given (`text` only for a pasted text). |
| `removeSource(caseId, sourceId)`, `restoreSource(caseId, sourceId)` | Marks a source removed, or not: its text stays in the data file and its PDF in the folder. |
| `readSourceText(caseId, sourceId)` | A pasted text's whole text (the list only carries its length and first words). |
| `choosePdfs(caseId)` | Opens the system's file dialog (PDFs, several at once); the main process reads each one chosen and copies it into the case's folder. |
| `addDroppedPdf(caseId, { name, data })` | A PDF dropped onto the window: its name and its bytes, read by the interface (at most 200 MB). Never a path. |
| `addFolderPdf(caseId, fileName)` | Adds, as it is, a PDF already at the top of the case's folder that no source uses. |
| `openSourcePdf(caseId, sourceId)` | Opens a PDF source's copy in the case's folder in the system's PDF viewer: only a plain file at the top of the folder, named `.pdf`, whose first bytes are a PDF's. |
| `onFlushSaves(listener)` | Before the window closes or the app quits, the main process asks the interface to save everything still waiting; the listener answers once nothing is under way (see "Closing, quitting and reloading" below). |
| `listFailedSaves()`, `retryFailedSave(id)` | The changes to sources that could not be saved, kept by the main process while the app runs; "Try again" runs one again (see "Changes that could not be saved"). |
| `startMockGeneration(generationId)` | Development check: runs the mock provider (no AI call, no key, no cost) with the real prompt builder and rules. The interface picks the id, a UUID. |
| `cancelGeneration(generationId)` | Stops a running generation. |
| `onGenerationUpdate(listener)` | Receives each generation's events (meta, status, text, done, error...) and a final `finished`; returns the function that unsubscribes. |
| `getConnections()` | The state of each AI connection: ChatGPT `not-connected` (with `savedAccount`), `signing-in` (with `otherPort`), `connected` (with the account's display name and `showWelcome`) or `needs-attention` (`plan-not-allowed`, `plan-not-eligible`, `session-ended`, `not-saved`); Claude `not-connected`, `connected` or `needs-attention` (`key-rejected`); and `problem` when the credentials file cannot be used. Never a key or a token. |
| `onConnectionsChange(listener)` | Receives the same state after every change (a sign-in, a refresh that ended the session, a key removed); returns the function that unsubscribes. |
| `saveClaudeKey(key)` | Checks the pasted key with Anthropic (the model list) and saves it only if accepted. Anything but a string of at most 1,000 characters is refused. Answers an outcome (`saved`, `not-a-key`, `rejected`, `unreachable`, `provider-error`, `not-saved`, `credentials-problem`), never the key. |
| `checkClaudeKey()`, `removeClaudeKey()` | Checks the saved key again; removes it. |
| `signInToChatGpt()` | Opens OpenAI's sign-in page in the system browser and resolves when the attempt ends, with its outcome. Takes no argument. |
| `cancelChatGptSignIn()`, `checkChatGpt()`, `signOutOfChatGpt()`, `forgetChatGptAccount()` | Stops a sign-in waiting for the browser; checks the sign-in (the account's model list); signs out (revoking the session with OpenAI); forgets a signed-out account ("Use a different ChatGPT account"). |
| `openChatGptUsage()` | Opens `https://chatgpt.com/settings/usage` in the system browser: a fixed address, no argument. |
| `dismissChatGptWelcome()` | Remembers in the settings file that "You're using your ChatGPT plan" was seen, so it is never shown again. |
| `startOverConnections()` | Only when the credentials file cannot be used: renames it aside, never deleting it, and starts empty. |

A generation belongs to the page that started it, and only that page can cancel it. When the page goes away (a reload or another navigation that actually happens, a renderer crash, the window closing), its generations stop and nothing more is sent for them: once real providers are connected, a generation nobody can see would otherwise keep spending. A navigation the app blocks (a link, a dropped file) leaves the page, and its generations, where they are; only a navigation that commits (`did-navigate`) counts. A window runs at most two generations at once (`MAX_RUNNING_PER_WINDOW` in `src/main/generations.ts`); a third is refused.

Rules for adding to it: one narrow function per action, plain data in and out, no generic "invoke anything", and never a key, a token or a file path the user did not choose. A key goes one way only: pasted into `saveClaudeKey`, never sent back. How the connections work, where the credentials file is and what goes to each provider: [connections.md](connections.md). Each handler first checks that the message comes from the top frame of the app's own window, showing the app's own origin.

No function takes a path. A case is named by its id (a UUID, checked with `isCaseId`), a source by its id (the same check), an unreadable folder or a PDF in a case's folder by its name inside that folder (one plain name, no separators, `.` or `..`), and a new cases folder or a PDF to add only ever comes from the system's dialog, which the main process opens. A dropped PDF, from any folder, arrives as bytes (owner's decision, 2026-11-22): the interface reads the dropped file and the main process never opens the original, so no interface code can make the main process read a file the user did not choose. Every argument is checked again in the main process with Zod, whatever the interface checked: wrong types, unknown keys, huge strings (capped before anything else looks at them) and paths are refused with a message that starts with "Refused:" and holds nothing from the disk. Expected outcomes (a missing folder, a damaged case) come back as values the interface explains; anything unexpected reaches it as a fixed sentence, with the details only in the main process's log. The cases folder's path is the one path the interface receives, as text to show the user where their cases are (owner's decision, 2026-11-22); nothing accepts it back.

## Security settings

Following Electron's security checklist (https://www.electronjs.org/docs/latest/tutorial/security):

- Context isolation on, sandbox on (also forced app-wide with `app.enableSandbox()`), no Node.js integration in the interface.
- A content security policy in `src/renderer/index.html`: only the app's own scripts, styles, images and fonts; no inline scripts or styles, no eval, no outside connections, no frames. Two changes made with the interface's base (owner's decision, 2026-11-22): `font-src 'self'`, so the IBM Plex fonts that ship inside the app can load (nothing comes from the network); and, under `pnpm dev` only, `scripts/dev-style-nonce.ts` adds a nonce, new on each run, to `style-src`, because Vite's dev server injects stylesheets as `<style>` elements. A built or packaged app carries the policy exactly as written in `index.html`; a window test checks it, and `tests/dev-style-nonce.test.ts` checks the plugin applies to the dev server only. Base UI's own inline styles are turned off (`CSPProvider`), so they need no exception.
- Navigation, redirects, new windows and `<webview>` are blocked for every page (`src/main/security.ts`). The interface moves between screens with React Router, which keeps the address in the URL's hash: a hash change stays inside the page and is not a navigation, so it is not blocked and does not stop a running generation.
- Every permission request and check (camera, microphone, notifications, devices...) is denied.
- The built interface is served from `app://aba-workbench/` rather than `file://` (`src/main/protocol.ts`); only files inside the built interface can be reached through it.
- IPC senders are validated (see above). Errors that reach the interface carry a safe message, never a path, a key or a request body.
- A packaged app ignores `ELECTRON_RENDERER_URL`, so an environment variable cannot point its window at another page.
- The provider SDKs are pinned to their official addresses (`https://api.anthropic.com`, `https://api.openai.com/v1`), and the ChatGPT sign-in's own requests to `https://auth.openai.com`, through the same fetch. A desktop app inherits the user's environment, and the SDKs read their base URL, extra headers, credentials, organization and telemetry settings from environment variables when not given them; each client is given every one of them explicitly. Its fetch sends nothing outside the official address and never follows a redirect: a redirect would re-send the request, documents included, to wherever it points, so a redirect answer is refused. `src/lib/providers/endpoints.ts` lists each variable and how it is neutralised; `tests/endpoints.test.ts` sets them all and checks where the requests go and what they carry. Outside the SDKs, Node's own settings (`NODE_OPTIONS`, `NODE_EXTRA_CA_CERTS`, proxy variables) still apply until Electron fuses are decided.

- The ChatGPT sign-in listens on `127.0.0.1` only, for one attempt at a time, and accepts one request: the callback with this attempt's state, addressed to its own host and port, sent as a top-level navigation ([connections.md](connections.md#signing-in-step-by-step)). The browser that signs in is the system's, never a window of the app.

Not done yet, by decision: Electron fuses, code signing, installers, automatic updates, keychain encryption of the credentials file.

## Where the rules are found

`src/main/paths.ts` decides: in development and in `pnpm preview`, the repository's `rules/` (next to `package.json`); in a packaged app, the `rules` folder that electron-builder copies into the app's resources folder (`ABA Workbench.app/Contents/Resources/rules` on macOS, `resources\rules` next to the `.exe` on Windows). A packaged build reads each rules file once; `pnpm dev` re-reads them on every generation, so edits show at once. Rules files parse with LF or CRLF line endings, and `.gitattributes` checks them out with LF everywhere.

## The settings file

`src/main/settings.ts` keeps the user's settings in `settings.json` in the app's data folder (`app.getPath("userData")`: `~/Library/Application Support/ABA Workbench` on macOS, `%APPDATA%\ABA Workbench` on Windows, `~/.config/ABA Workbench` on Linux). It holds the screen language, once the user has chosen one in Settings the cases folder, and once "You're using your ChatGPT plan" was dismissed `chatgptWelcomeShown: true` ([connections.md](connections.md#signing-in-step-by-step)): `{ "version": 1, "language": "es", "casesFolder": "/Users/ana/Casos", "chatgptWelcomeShown": true }`. Each optional key is written only when set. The default cases folder is not written, so it follows the home folder. Only the main process reads or writes it; the interface asks through `getSettings`, `setLanguage`, `getCasesFolder`, `chooseCasesFolder` and `dismissChatGptWelcome`. A cases folder in the file that is not an absolute path is ignored, never guessed at.

- Read back through Zod, field by field: a missing file means a first run (the language follows the system's preferred languages, Spanish or else English); a file that is not JSON, or holds a value this version does not know, falls back to the defaults for what it cannot use and keeps the rest. The main-process log says so; the next change rewrites the file whole.
- Written durably (`src/main/durable-write.ts`, shared with the cases): a temporary file next to it, flushed to the disk (`datasync`), renamed over it, then the folder flushed so the rename itself survives a power cut (on macOS and Linux; Windows cannot open a folder for that, and NTFS journals the rename). A crash or a power cut mid-save leaves the old file or the new one, never half of either. A failed save removes the temporary file and reports a safe message to the interface, which still shows the chosen language for the session and says it was not saved. Saves run one after another.
- When a language cannot be saved, the interface asks the main process which language is saved (the one the app will open in next time) rather than assuming it is the one that was on screen, and the sidebar and Settings read the same state (`src/renderer/src/language.tsx`), so after several failures in a row both name the right language.
- `tests/settings.test.ts` covers a first run, a corrupt file, an outdated one, refused values, the cases folder (kept, refused when not absolute, not written when it is the default), quick successive saves, a save that cannot replace the file (no temporary file left) and a failed save.

## Cases

Each case is a folder inside the cases folder, holding its data file, `aba-case.json`, and its PDFs as they are (never converted or embedded). Only the main process touches them (`src/main/cases.ts`); the interface names a case by its id.

### Where

The cases folder is `ABA Workbench` directly in the user's home folder (`app.getPath("home")`: `~/ABA Workbench` on macOS and Linux, `%USERPROFILE%\ABA Workbench` on Windows) unless the user chose another in Settings, through the system's folder dialog; the choice is saved in the settings file. `src/main/cases-folder.ts` checks it before use and reports one of: `ready`; `not-created-yet` (the default, not made yet, inside a home folder that exists); `missing` (a chosen folder that is gone, an unplugged drive say); `not-a-folder`; `not-allowed` (the system refuses to let the app look inside: on macOS, the answer to the prompt for a protected folder the user chose was no); `not-writable`.

**Why the home folder, not Documents** (owner's decision, 2026-11-22). Clients' health data must not go to a personal cloud without the user choosing it, and a personal OneDrive or iCloud has no HIPAA business associate agreement. Documents is often synced; the home folder itself is not, by default, on either system:

- macOS: iCloud's "Desktop & Documents Folders" stores only those two folders in iCloud Drive: "When you turn on Desktop & Documents Folders, your Desktop folder and Documents folder are stored in iCloud Drive" ([Apple, Add your Desktop and Documents files to iCloud Drive](https://support.apple.com/109344)).
- Windows: OneDrive's Known Folder Move redirects "Desktop, Documents, Pictures, Screenshots, and Camera Roll" ([Microsoft, Redirect and move Windows known folders to OneDrive](https://learn.microsoft.com/sharepoint/redirect-known-folders)); the consumer folder backup offers "Desktop, Documents, Music, Pictures, and Videos" ([Microsoft, Back up your folders with OneDrive](https://support.microsoft.com/office/back-up-your-folders-with-onedrive-d61a7930-a6fb-4b95-b28a-6552e77c3057)). The profile folder itself is in neither list.
- macOS privacy: the folders an app needs permission for are Desktop, Documents and Downloads ([Apple, Control access to files and folders on Mac](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)), plus iCloud Drive, cloud storage, removable and network volumes; Apple's list of protected resources has a usage-description key for each and none for the home folder ([Apple, Protected resources](https://developer.apple.com/documentation/bundleresources/protected-resources)). A folder made directly in the home folder needs no prompt. (Checked 2026-11-22; not tried on a real Mac's first run.)

The interface says only what the app controls: ABA Workbench sends nothing anywhere, and if the chosen folder is synced (OneDrive, iCloud, Dropbox, Google Drive), that service copies it. Settings says so in one sentence where the folder is chosen. On macOS and Linux "writable" is the permission bits; on Windows, where access rights and Controlled folder access decide, it is checked by making one empty file and removing it at once, only when a folder is chosen in Settings and when a case is created, never when Home lists the cases or a case opens (each check could raise a Windows Security notice, or a sync in OneDrive).

The app never creates a folder in a place the user did not expect. The default folder is made, one level only, inside the existing home folder, when the first case is created. A chosen folder that has gone missing is reported, with a way to choose another, and is never made again.

**`--home-folder`, development only** (owner's decision, 2026-11-22). The built app's window tests start it with `--home-folder=<a temporary folder>`, which stands in for the home folder (it must be an absolute path), so no test reads or writes the real one; it only changes the default, and a folder chosen in Settings wins. A packaged app ignores it (`resolveHomeFolder` in `src/main/paths.ts`): nothing typed on a command line or in a shortcut can move where a packaged app keeps clinical data. The packaged window tests write a temporary cases folder into their temporary profile instead, run the two tests that need the default folder (a corrupt or unwritable settings file) on the built app only, and check that the packaged app ignores the option. (Electron's home folder does not follow the `HOME` variable on macOS, so it cannot stand in for this.)

### The data file

`src/main/case-file.ts`. Schema version 1 holds what Phase 1 needs and no more:

| Key | What it holds |
| --- | --- |
| `schemaVersion` | `1`. |
| `id` | A version 4 UUID, lowercase, made when the case is created. The interface uses it in the case's address (`#/cases/<id>/sources`). |
| `label` | What the user typed: Unicode NFC, no spaces at either end, 1 to 100 characters, no control or text-direction characters (`checkCaseLabel` in `src/shared/api.ts`). |
| `clientAge` | `{ "years": 0-120, "months": 0-11 }`, `months` optional; left out when the user gave no age. |
| `createdAt`, `updatedAt` | ISO 8601 in UTC. `updatedAt` moves on every save, always forward (a millisecond past the last one if the clock says otherwise). |
| `files` | The PDFs at the top of the case's folder: `{ name, bytes, modifiedAt }`, by name. Hidden files and links are left out. Opening a case refreshes the list and saves the case if it changed; so does every change to its sources. |
| `sources` | Version 2. The case's sources, oldest first (below). |

Schema version 2 (`CASE_SCHEMA_VERSION`) adds `sources`. Each entry:

| Key | What it holds |
| --- | --- |
| `id` | A version 4 UUID, made when the source is added. |
| `kind` | `"text"` (pasted) or `"pdf"`. |
| `type` | One of `SOURCE_TYPES` in `src/shared/sources.ts`, one list for pasted texts and PDFs (owner's decision, 2026-11-22): `cde`, `parent-interview`, `direct-observation`, `fba-questionnaire`, `iep`, `vineland-3`, `basc-3`, `ablls-r`, `other`. A type this version does not know (lowercase letters, digits and `-`, from a newer app) is kept as written and shown as "Other". |
| `title`, `date` | Optional, left out when not given. The title is checked like a case's label (NFC, trimmed, 1 to 120 characters, no control or text-direction characters); the date is a calendar day, `"2026-10-02"`. |
| `addedAt`, `updatedAt` | ISO 8601 in UTC. |
| `removedAt` | Present when the clinician removed the source from the case. Nothing is deleted (owner's decision, 2026-11-22): the text stays here, the PDF in the folder, and restoring the source takes the key away. |
| `text` | A pasted text, as pasted (line endings made `\n`), at most 1,000,000 characters. |
| `file`, `bytes` | A PDF: its copy's name at the top of the case's folder, and its size when it was added. |

Pasted texts are kept in the data file, not in files of their own (owner's decision, 2026-11-22), so one durable write saves a change whole and the reading rules below cover them. A case holds at most 500 sources, and its data file at most 50 MB (`MAX_CASE_FILE_BYTES`): a change that would make it larger is refused whole (`case-full`), never cut.

Later phases add their own top-level keys (behaviors, drafts) and raise `schemaVersion`.

**Reading.** The data file is read as bytes and decoded as UTF-8 with no replacement: a file that is not valid UTF-8 (one saved as Latin-1 by an older Windows Notepad, say) is damaged. So is a file that `JSON.parse` would read with less than it holds: an object with a repeated key (the last would win), a key named `__proto__` (rebuilding the object turns it into the prototype, and a save drops it), or a number that does not read back as itself (one too large for any number, a whole number past 2^53, a decimal with more digits than a number holds, a tiny number read as 0, or -0, written back as 0). Numbers the app writes always pass: `JSON.stringify` writes each so it reads back exactly. A damaged file is never written to, so the app never saves a case with less than its file held (`readCaseFile` and `parsesWithoutLoss` in `src/main/case-file.ts`).

**Versioning.** `CASE_SCHEMA_VERSION` is the version this app writes. Reading a file: a higher version (a newer app wrote it) is unreadable as "newer-version" and never written to; a lower one is migrated in memory, one version at a time (`MIGRATIONS[n]` turns version n into n+1: `MIGRATIONS[1]` gives a version 1 file an empty `sources` list), and written in the current version on its next save, including the save opening makes when the folder's PDFs changed (after that, an older app shows the case as from a newer version); a missing step, or a version that is not a positive whole number, makes it damaged. A key this version does not know (at the top, inside `clientAge`, on a file entry or on a source) is kept as it is when the case is saved; the interface only ever sees the keys it knows. To change the shape: raise `CASE_SCHEMA_VERSION`, add the step to `MIGRATIONS`, update the schema, and add a test that an old file migrates.

**Saving.** Every write goes through `writeFileDurably` (see the settings file above). Saves of one case run one after another. A save cut short by a crash or a power cut leaves a temporary file, `aba-case.json.<process id>.tmp`, a full or partial copy of the case's data. **The app never deletes a case folder or anything in it** (owner's decision, 2026-11-22): it recovers, or it shows.

- **An interrupted creation.** A case folder with no `aba-case.json` that holds exactly one file, a temporary data file (checked with `lstat`: a plain file, never a link), is a case the app was creating when it stopped. If it is not still being written, and it reads as a complete case under the same strict reading as `aba-case.json` (UTF-8, lossless, the schema), with an id no other listed case has, Home's listing finishes the creation: that file is renamed to `aba-case.json` and the folder flushed, as the save would have done (`finishInterruptedSave` in `src/main/durable-write.ts`), and the case is listed. Otherwise the folder is listed as `unfinished` and nothing in it changes. Two temporary files (two saves were attempted, and a partial one may be the newer change) or a temporary file next to anything else are never touched: the app does not choose for the user.
- **An interrupted save of an existing case.** The temporary file next to `aba-case.json` may hold the user's latest change, so it is never removed; it stays, untouched, and the case opens from `aba-case.json`.
- **The settings file**, outside any case folder, holds only the app's preferences and is rewritten whole by the next save: its leftover temporary files (plain files, not one being written) are removed when the app starts.

"Still being written" means a temporary file this process is writing now (it keeps a list: a name cannot say it, since a crashed earlier run may have had the same process id), or one that has changed in the last minute (`isLeftBehind`). Only one copy of the app runs per profile (`app.requestSingleInstanceLock()` in `src/main/index.ts`; a second start shows the window already open and quits), but two profiles or two computers can share a cases folder (a network or synced folder), so a file untouched for a minute is treated as left behind. The minute is a guess from the file's modified time and can be wrong (a network server's clock far behind, a save hung for over a minute); it only decides when an interrupted creation is finished, so the worst case is that another copy's in-flight creation is finished for it and its own rename then fails, which it logs; nothing is deleted. The age is used nowhere else.

**Saving never touches a file it did not create.** `writeFileDurably` creates its temporary file exclusively (`wx`) as `<file>.<process id>.tmp`; when that name is taken (a crashed earlier run with the same process id, since ids are reused after a reboot, left a file that may hold the user's latest change), it tries `<file>.<process id><n>.tmp` and leaves the existing file as it is. Every name is `<file>.<digits>.tmp`, so recovery recognizes it.

**The one exception** (owner's decision, 2026-11-22): when a save fails while the app is running (a full disk, a refused rename), it removes the temporary file it created in that same failed call, and only that one: a flag set when that call creates the file guards the removal, so it can never remove a file the call did not create. That file holds only what the call was writing, which the user still has: the New case dialog stays open with what was typed, a case's PDF list is rebuilt at every open, and a later phase's `update` reports the failure while the change is still on screen. Keeping it would leave a copy of data the user was told was not saved, which the next listing could even recover. Creating a case that fails that way also removes the empty folder it had just made (`rmdir`, which refuses a folder with anything in it).

**Every place the app removes a file:**

| Where | What | Why it is safe |
| --- | --- | --- |
| `writeFileDurably`, on failure | The temporary file this same call created | The `created` flag: never a file the call did not create; it holds only what the failed call was writing. |
| `CaseLibrary.create`, on failure | The case folder it had just made (`rmdir`) | Empty by then; `rmdir` refuses a folder with anything in it. |
| `removeLeftoverAppDataTemporaryFiles`, at start | `settings.json.<digits>.tmp` and `credentials.json.<digits>.tmp` in the app's own data folder | Never a case folder; plain files only (`lstat`), not one being written; the settings hold only the app's preferences and the credentials only what the user can sign in again for, and one copy runs per profile. |
| Windows' write check (`cases-folder.ts`) | The empty check file it just made | Created exclusively under a free name; a taken name is left alone. |
| `writeNewFile` (`case-pdfs.ts`), on failure | The partial PDF copy this same call created | Created exclusively (`wx`), so it can only be the call's own file; the user still has the original. |

Nothing removes the credentials file itself: "Start over" renames an unreadable one aside ([connections.md](connections.md#where-credentials-live)), and removing the Claude key or signing out rewrites the file without them.

The saves themselves replace `aba-case.json`, `settings.json` and `credentials.json` by renaming the new version over them, which is what a save is for; recovery's rename never replaces an existing `aba-case.json` (it checks with `lstat` first; the instant between the check and the rename is not atomic, and nothing in the app writes `aba-case.json` into such a folder in that instant).

**Finding a case.** The main process remembers each case's folder from the last listing, and the cases folder that listing read. Opening or saving a case lists again when the cases folder has changed since (a case in the old folder is then not found, never read or written), or when its folder no longer holds that case (renamed or moved in Finder or Explorer while the app was open: it is found under its new name). A case is only ever read or written inside the cases folder in use. `CaseLibrary.update(id, change)` is the save later phases use: it reads the case as on disk, applies the change, moves `updatedAt` and writes it durably. A case's label and age are not edited in this phase (owner's decision, 2026-11-22): a case is saved when it is created, when opening it finds its PDFs changed, and on every change to its sources.

### Sources

`src/main/case-sources.ts` (the changes, on the data alone) and `src/main/case-pdfs.ts` (copying PDFs); `CaseLibrary` runs them on disk. The Sources step in the interface is described in [interface.md](interface.md#the-sources-step).

- **One change at a time, in order.** Each change to a case's sources joins that case's line before anything is awaited, then reads the data file as on disk, applies the change, and writes it durably with a new `updatedAt`. Two quick saves of a text (typing, then leaving the field) are written in the order they were asked for, so the older never lands last. A case that is gone, damaged or from a newer version answers `case-unavailable` and is never written.
- **Adding a PDF copies it, as it is.** From the dialog the main process reads the chosen file (it never writes, moves or renames it); a dropped one arrives as bytes. Either must start with `%PDF-` (within its first 1024 bytes) and be at most 200 MB (`MAX_PDF_BYTES`). The copy is named from the original's name made safe like a folder name (`pdfFileNames` in `case-folder-name.ts`: `Document.pdf` when nothing is left), ` 2`, ` 3` when the name is taken (ignoring case), and created exclusively, so no file is ever overwritten; the folder is then flushed. A PDF whose exact bytes are already in the folder is not copied again: it is reported as already added (or already removed), or, if no source uses that file, the file itself becomes the source. Its type is guessed from its name (`guessPdfType`).
- **A crash mid-copy** can leave a partial PDF in the case's folder. The data file is saved only after the copy, so it is never a source; the Sources step lists it with the folder's other PDFs, where the clinician sees it. A copy that fails while the app runs removes its own partial file (the table above).
- **PDFs put in the folder by hand** are listed under "Also in this case's folder" with an Add button; they become sources only when the clinician adds them (owner's decision, 2026-11-22). Adding one reads it to check it is a PDF and changes nothing.
- **Renaming** a source changes its title in the data file only; the PDF keeps its name on disk (owner's decision, 2026-11-22).
- **A PDF source whose file is gone** (moved or renamed in Finder or Explorer) is shown as missing and cannot be opened; nothing else changes.
- **Opening a PDF** hands the system's viewer only a plain file (never a link) at the top of the case's folder, named `.pdf`, whose first 1024 bytes hold `%PDF-` (`sourcePdfPath`, `isPdfFile`). A data file copied or received from elsewhere could name any file, a program say, which the system would run rather than show; such a source does not open. The stored schema is not tightened, so such a file still reads (and is never written with less).
- **Copied but not added.** When a PDF has been copied in but the data file then cannot be saved, the answer says so (`copied-not-added`, with the file names): the copy stays in the folder, under "Also in this case's folder", where the clinician can add it.
- **A `sources` key in a version 1 file.** `MIGRATIONS[1]` keeps a `sources` key already in a version 1 file (no version of the app wrote one) and it must then read as version 2's: a version 1 file holding some other `sources` key reads as damaged, and is never written.

- **Size.** When a PDF is added, its size is compared with what each provider takes in one request (`pdfSizeWarning` in `src/lib/limits.ts`, from the limits below): over about 37.5 MB, ChatGPT would refuse it; over about 96 MB, Claude too. The Sources step says so on the PDF at once, and again when the case's PDFs together are over a limit.

### Changes that could not be saved

`src/main/failed-saves.ts`. Every change to a case's sources goes through `FailedSaves` in the main process. A change that could not be saved (`not-saved`, `case-full`, `case-unavailable`, `source-not-found`, or an unexpected error) is kept there, with what it was trying to write, for as long as the app runs, so a reload of the window forgets nothing. The interface reads the list (`listFailedSaves`) after every save and when its page starts: Home lists each case with such a change, and the step shows it with "Try again", which runs the same change again (`retryFailedSave`). A later change to the same thing that is saved replaces a failed one (a text, a title, a type, a date, a removal; a new text is matched by its text, so another new text never clears it). A refused input is never kept. Closing or quitting asks first while any is left (below).

### Closing, quitting and reloading

Nothing the clinician typed is lost when the window closes, the app quits, or the page reloads, on any system (on Windows and Linux, closing the last window quits). `src/main/close-guard.ts`, wired in `src/main/index.ts`:

- The window's first `close` (from its close button, Cmd+Q, `app.quit()`) is held back. The main process asks the interface to save (`flushSaves`): every screen with typing still waiting for its pause saves it at once (a text, a title), and the interface answers once no save is under way. The main process then waits for its own case work (`CaseLibrary.idle`). Both waits share one deadline of 5 seconds (`SAVE_WAIT_MS`), so she never waits longer before being asked.
- If a change could not be saved (as the interface says, or as `FailedSaves` holds), or saving did not finish in time, a message box in the screen language asks her: "Go back" (the default: the window stays, the quit is called off, and the step shows what failed with "Try again") or "Close anyway". A page that has crashed has nothing left to save, so it does not ask.
- Otherwise the window closes, and a quit goes on. The preload always answers the request (at once when no screen has set a listener), so a page that never finished loading does not hold the window.
- **Reloading.** When the page is about to unload (a reload: Reload or Force Reload in a development build's menu, or the page reloading itself), it sends at once what is still waiting for a typing pause: each save sends its change before its first pause, so it reaches the main process even as the page goes. While any save is still under way it holds the unload (`holdUnloadForSaves` in `src/renderer/src/case-saves.tsx`); the main process (`will-prevent-unload`) then waits for those saves, within the same 5 seconds, and reloads. If a save is still under way then (one that hangs, on a stuck disk say), the page holds the unload again and the main process waits again, every 5 seconds and without a message, until the save ends: the reload is postponed, and nothing is lost (a follow-up: after the first wait, ask "Go back / Reload anyway"). What could not be saved stays in `FailedSaves` and shows again on the reloaded page. A new text's address names it once it exists (`#/cases/<id>/sources/text/<source-id>`), so a reload opens the text, not a new empty one.
- **Quitting** has one wait for everything that must not be cut short (`createQuitWait`, one `before-quit` listener): with no window open (macOS), case work still under way (up to 5 seconds), and the last try to save a renewed ChatGPT sign-in that could not be saved (up to 3 seconds, [connections.md](connections.md)), both together, then the quit.

### The menu

`src/main/app-menu.ts` (owner's decision, 2026-11-22; this replaces "developer tools decided together with signing"). A development build (`pnpm dev`, the built app the window tests run) keeps Electron's default menu, with Reload, Force Reload and Toggle Developer Tools. The packaged app has none of those, nor their keyboard shortcuts, and its window cannot open the developer tools at all (`webPreferences.devTools` is false when packaged): it has the macOS app menu (About, Hide, Quit...), File, the standard Edit menu on every system (undo, redo, cut, copy, paste, select all), View with zoom and full screen only, and Window. A window test checks both.

### Folder names

`src/main/case-folder-name.ts`, from the label (owner's decision, 2026-11-22): Unicode NFC; the characters Windows forbids (`< > : " / \ | ? *`) and control characters become `-`; runs of spaces collapse to one; dots and spaces at the start and at the end go; at most 60 characters, cut between whole characters; an empty result becomes `Case`; a Windows device name (`CON`, `PRN`, `AUX`, `NUL`, `COM0`-`COM9`, `LPT0`-`LPT9`, also with superscript digits, any case, with or without an extension) gets ` case` after it. A name already in the cases folder, compared ignoring case and Unicode form (as macOS and Windows do), gets ` 2`, ` 3` and so on. The folder is made with an exclusive create, so an existing folder is never touched, even one that appears between the check and the create; if the data file then cannot be written, the new empty folder is removed.

### Unreadable folders

`listCases` reads every folder at the top of the cases folder (hidden folders and loose files are left out). Cases are listed newest first by their created time, compared as times, with ties in folder-name order. A folder it cannot open as a case is listed below the cases, under "Folders that could not be opened", with the reason in plain words and a "Show in Finder" ("Show in Explorer" on Windows) button (owner's decision, 2026-11-22): `not-a-case` (no `aba-case.json`), `damaged` (not JSON, a value missing or wrong, a data file larger than 5 MB, a folder or a link in its place), `newer-version`, `duplicate` (the same id as a case listed before it, by folder name: a copied folder), `cannot-read` (the system refused), `link` (a symbolic link to a folder elsewhere: never followed, since it could lead out of the cases folder, but shown so nothing is silently missing; "Show in Finder" shows the link itself). The app never changes such a folder, with one exception: finishing an interrupted creation (above), which renames the app's own complete temporary data file to `aba-case.json` and changes nothing else; a folder it cannot finish is listed as `unfinished` (a case that was not finished being created). One bad folder never hides the others.

### macOS's permission for a protected folder

The default cases folder, in the home folder, needs no permission. macOS asks the user before an app opens Documents, the Desktop, Downloads, an external or a network drive, or a folder a cloud storage app such as OneDrive, Dropbox or Google Drive manages through a File Provider (under `~/Library/CloudStorage`), so a cases folder the user chooses in one of those places can bring a prompt. The packaged app's `Info.plist` carries `NSDocumentsFolderUsageDescription` and the five others in plain words, each saying the cases are in the folder chosen in Settings, never that the app keeps them in Documents (`NSFileProviderDomainUsageDescription` is Apple's documented key for the File Provider prompt, macOS 10.15 and later) (`electron-builder.yml`, `mac.extendInfo`), and `packaging/macos/<language>.lproj/InfoPlist.strings` gives them in English and Spanish (`es` and `es_419`, which a Mac set to Latin American Spanish looks in first); `tests/packaging.test.ts` keeps them in step and the packaged window tests check they ship. If the user says no, reading the folder fails with `EPERM`: Home and Settings say ABA Workbench is not allowed to open the cases folder, how to allow it (System Settings, Privacy & Security, Files & Folders), and offer to choose another folder. A folder chosen in the dialog is one the user picked, so macOS lets the app open it.

## Packaging

`pnpm package` runs `electron-vite build` and `electron-builder --dir` with `electron-builder.yml`: an unpacked app for the current platform and architecture in `dist/`, unsigned, with the default Electron icon. The app archive holds only `out/` and `package.json`; the provider SDKs and Zod are bundled into `out/main/index.js`, and the interface, with its fonts, is in `out/renderer/`. Next to the archive, in the resources folder, are `rules/` and `licenses/` (the IBM Plex fonts' SIL Open Font License, which must travel with them; the packaged window tests check it is there).

## macOS and Windows

## Size of a request

Before anything is sent, `runGeneration` checks the request against its provider's documented limit (`src/lib/limits.ts`, one entry per provider next to its source; checked 2026-11-22). Over the limit, the generation ends with a `request_too_large` error whose message gives the request's size, the limit, and what to do: remove a PDF, or paste the text of a report instead of attaching its PDF. `pnpm phase0` runs the same check for every case before it spends anything.

| Provider | Documented limit | What is counted |
| --- | --- | --- |
| Claude | 128 MB per Messages request ([request size limits](https://platform.claude.com/docs/en/api/overview#request-size-limits), [PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)) | The whole request: rules, sources with PDFs as base64, section request. |
| OpenAI | 50 MB of files per request, each file under 50 MB ([file inputs](https://developers.openai.com/api/docs/guides/file-inputs)) | The PDFs as sent, in base64. The page does not say whether a base64 file counts at its file size or its encoded size, so the stricter reading is used: about 37.5 MB of PDF fills it. The message gives both sizes in that order ("are 40.0 MB; sent to OpenAI they become 53.3 MB, over its 50 MB limit"), so it does not seem to contradict itself. |

Megabytes are decimal (1,000,000 bytes); the pages do not say which, and decimal is the smaller.

**Claude's page limit.** Claude reads at most 600 PDF pages in one request, or 100 when the request's context window is under 1M tokens; both models this project uses (Opus 5.5, Fable 5.2) have 1M-token windows, so 600 applies. Pages are not counted before sending: a reliable count needs a PDF parser (in current PDFs the page objects usually sit inside compressed object streams, and a regex count can also double-count pages kept from earlier revisions). Instead, when Claude refuses a request with an error shaped like that limit (it names PDFs and pages, and a word such as "maximum", "exceed" or "too many"), the message says Claude accepts 600 pages per request for the models this app uses, says what to do, and keeps Claude's own words. Anthropic's documentation does not give the exact wording of that error, so any other refusal keeps Claude's message as it is. A 413 from either provider gets the same kind of message.

The 4.5 MB cap that Phase 0 had was Vercel's request limit; it no longer exists (owner's decision, 2026-11-22).

## Continuous integration

`.github/workflows/ci.yml` runs the same steps on Linux (`ubuntu-24.04`), Windows (`windows-2025`) and macOS (`macos-26`), with `fail-fast` off: install, lint, typecheck, unit tests, build, `pnpm phase0 --mock` and the window tests.
